# AgentDesk 能力边界与界面改版

日期：2026-10-06。能力定义以 `AGENTS.md`、机器契约及当前实现为依据；本文件记录界面决策，不改变 Agent、Tool、数据库或 API 契约。

## 已确认的决定

用户确认面向作品集评审与项目演示者；整体改造登录、工单、审批、轨迹和评估五个页面；明确标注当前演示与验收状态。能力范围详见 `README.md` 的“系统边界”章节。本轮不修改 `AGENTS.md`。

## 应用技能与设计取舍

先使用 `grill-me` / `grilling` 进行事实盘点和决定确认，之后使用 `ui-ux-pro-max` 的本地检索。查询 `service desk operations dashboard` 与 `internal operations dashboard` 的 design-system 输出支持适用于企业后台的 Minimalism & Swiss Style、浅色工作区、高对比文字和低幅度交互。返回的 Hero + Features + CTA 属于营销页面，复查后仍不适配工作台，未将该布局或未验证的生成结果持久化。

以下工作台布局由实际使用流程确定：深蓝侧栏与统一导航、浅灰画布、白色列表／详情区域、蓝色主要操作。系统字体兼容中文，等宽字体只用于标识；不依赖远程字体和图标资源。沿用 Vue 3、Pinia 和已生成的 API 类型，复用轻量页面外壳与 SVG 图标，不引入新的 UI 框架或设计系统库。

## 各页职责

| 页面 | 主要行动 | 支持信息与边界 |
|---|---|---|
| 登录 | 输入已配置的演示账号 | 简述自然语言请求、治理和追溯；说明模拟环境；提交后清除密码，Token 仅内存保存 |
| 工单 | 创建请求、选择工单、跟进结果 | 请求示例只填入文本、不自动提交；列表统计只来自当前可见工单；引用可展开文档／片段与检索分数；人工审批／接管明确显示 |
| 审批 | 核对固定参数，通过或拒绝 | 脱敏参数、风险、有效期在主区域；ID 和 hash 渐进展开；提交版本沿用既有后端契约 |
| 轨迹 | 按工单 ID 查询、按事件类型筛选 | 所有顺序号来自原始记录；计数包含工具尝试；摘要保留原文，标识渐进展开；不把审计过程描述成当前全量安全验收成绩 |
| 评估 | 选择已登记运行、查看结果来源 | 固定门槛与本次观测分列；live 不自动等于 E2E；基线／阶段／分母缺失时不给完整通过结论；本地 JSON 不自动填充数据库记录 |

## 交互与验证要求

- 选择列表项使用原生按钮，键盘可达；表单字段有标签、错误有 alert 语义；导航显示当前位置。
- 保留加载、空状态、错误、成功、等待审批、过期及失败路径。
- 桌面展示列表与详情；小屏转为单列和顶部导航；长 ID 允许换行，宽表格局部滚动。
- 支持可见焦点、跳转工作区和减少动画的系统设置。
- 验证包括前端 lint、类型检查、现有 Vitest 回归、生产构建以及浏览器桌面与小屏渲染。浏览器使用固定示例响应时，只证明前端渲染和交互，不证明真实模型／Worker／数据库端到端完成。

## 本轮完成与证据

五个页面已实现上述布局与交互。Node.js 22.22.2 下 lint、type-check、18 个 Vitest 测试和生产构建均通过；桌面／手机浏览器截图、固定响应说明及验证范围见 [界面验证记录](../../output/playwright/README.md)。API、Agent、Tool、数据库契约和项目依赖未因本轮界面改版变更。
